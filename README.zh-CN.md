# 工时表语法生成实验

本仓库是一个独立的本地实验，为 Payslate Online 的防御性健壮性测试生成合成工时表 CSV。仅使用 Python 3.12 标准库，不涉及网络服务。

```sh
python3 generate.py --seed 7 --count 3
python3 -m unittest discover -v
```

输出会标明每个文件的起止位置；这些标记仅用于展示，不属于 CSV 内容。调用 `derive("file", random.Random(seed), 8, covered)` 可得到单个文件的文本，编码为 UTF-8 后可保留可选的文件开头 BOM。相同种子和设置会生成相同的文件。

`grammar.json` 用列表保存每条规则的备选项，并通过 `<rule>` 引用其他规则。数据行数限定为一至五行（N = 5），修改对应备选项即可调整上限。`--depth` 默认为 8；推导达到深度上限时会明确报错。覆盖统计记录选中的 `(规则, 备选项索引)`，包括空字符串选项；它不代表组合覆盖率，也不代表产品代码覆盖率。

语法涵盖逗号、分号和制表符分隔，可选 BOM、LF/CRLF、表头别名及大小写变化、可选节假日字段、带引号字段、引号内的分隔符、双引号转义和空行。日期取自 2026 年 6 月至 7 月 12 日，均为有效日期。时间采用两种受支持的格式，包含跨夜班次，起止时间不会相同。每个文件只选择一次分隔符和换行符，并在推导过程中共享；可选列的表头与所有数据行也共享同一选择。

ADR 0003 要求拒绝未知表头。排班软件导出的文件常带备注、休息时长之类的列，因此语法也会加入可选的 `notes` 和 `break minutes` 列，用来探索这一边界：含有这些列的文件在 CSV 结构上有效，但不符合可接受的表头约定。空行不含字段，检查列数时会跳过。产品尚未决定是否支持引号内换行，因此本语法不生成这种情况。

## 比较两种策略

```sh
python3 compare.py --budget 1000 --seed 120012
```

两种策略各生成恰好 `budget` 个候选文件，分别使用以相同种子初始化的随机数生成器。语法策略每次重新推导文件；变异策略每次都从同一个逗号分隔的原始文件开始，其中包含三名合成员工、2026 年 7 月初的日期和节假日列。每个候选文件随机执行一至三次字节覆盖、插入或删除；操作、位置和新字节均匀抽样。覆盖可能没有改变原字节，多次操作也可能相互抵消；重复文件仍计入预算。因此这里比较的是候选文件数量，不是运行时间或字节数。

命令只输出一行 JSON。`seed` 和 `budget` 标识本次运行；`grammar_alternatives_covered` / `grammar_alternatives_total` 表示已选中过的语法备选项数量与总数；`grammar_accepted` 和 `mutation_accepted` 表示通过本地检查的文件数。两个 `*_distinct_rejections` 字段统计各策略触发的不同首个拒绝原因类别，不代表文件中的全部缺陷，也不代表产品内部路径数量。

本地接受检查只用于近似衡量输入能否通过解析与校验，不能替代产品的判定。它按 UTF-8 解码并允许开头 BOM，从表头推断分隔符、识别别名、检查列数、校验日期和时间、拒绝相同起止时间，并校验节假日值。它还会拒绝未知或重复表头、空员工姓名、数据中的 BOM、单独的 CR 和格式错误的 CSV，跳过空行。日期只做日历有效性检查，不受生成器日期范围限制。没有节假日列时按 false 处理。检查只返回分类结果，不验证产品是否正确保留解析后的布尔值。

本实验会拒绝只有表头而没有数据的文件，以及引号内换行；ADR 0003 尚未确定产品对后一种情况的处理方式。CSV 解析使用 Python 的 `csv` 模块，分隔符推断采用简化的本地规则。本检查没有实现产品导入器、HTTP 处理、流式处理限制或后续工资计算规则。语法生成的额外列会触发 `unknown_header`。后续产品测试必须依据 HTTP 响应判定结果，并在产品边界验证解析值。

实际运行结果和后续建议见 [实验结果](FINDINGS.zh-CN.md)。
